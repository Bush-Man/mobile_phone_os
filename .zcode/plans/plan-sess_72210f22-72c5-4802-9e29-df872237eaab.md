## Fix plan for the `make run` failures

Twelve changes across kernel, drivers, net and the userspace libc. Ordered so the shared root causes land first — several suites should recover without touching them directly.

### 1. Ramfs/fat32/ext2 vnodes are born with `refs == 0` (fixes 9 `fstest` failures + kmsg + SMS store + battery node)
The mount root is freed by the first path walk, leaving `mounts[0].root` dangling, so every resolve returns `-ENOTDIR`.
- `fs/ramfs.c` `shell_make()`: add `vn->refs = 1;` (the comment at `fs/ramfs.c:113` already claims this contract; `fs/devfs.c:48` honours it).
- Same one-liner in `fs/fat32.c` `inode_shell()` and `fs/ext2.c` `shell_from()` — latent today because no disk is attached under `make run`.

### 2. `waitpid` from kernel tasks (fixes 4 "reaped" failures)
- `kernel/proc.c` `reapable_exists()`: invert to `== NULL` — `wait_sleep_when()` parks while the predicate is true, so the current form sleeps exactly when a child *is* reapable.
- Switch the five kernel-task callers from `proc_do_waitpid()` to the already-written but unused `proc_kernel_reap()`, polling with `msleep(10)` until it returns non-zero: `kernel/main.c:143`, `kernel/selftest_userspace.c:69` and `:89`, `kernel/selftest_ui.c:103`, `kernel/selftest_release.c:140-141`.

### 3. Userspace `snprintf` reverses digits (fixes 3 libctest failures + the bogus `pid 71` / `code 731` prints)
- `userspace/libc/stdio.c` `emit_u64()`: reverse `tmp[0..n)` in place before `pad_emit`.

### 4. Network: double Ethernet header + no ARP flush (fixes 5 `nettest` failures)
- `net/etharp.c`: `arp_send_raw()` and `arp_send_ip()` must hand `link_out()` the *payload*; both `lo_out()` (`net/netif.c:113`) and `eth_link_out()` (`kernel/phase11.c:22`) prepend their own header. Store the pending frame as payload-only too.
- `net/etharp.c` `arp_input()`: after `cache_put()`, if a pending frame matches the learned IP, transmit it through `link_out()` and clear the slot.
- `net/tcp.c` `tcp_connect()`: set `snd_inflight = true` *before* `tcp_xmit()` — loopback delivery is synchronous, so the SYN-ACK handler clears the flag before line 251 sets it, wedging the next write.

### 5. Audio backend selection and scaling (fixes 6 `audiotest` failures)
- `kernel/phase13.c`: stop registering the I2S scaffold unconditionally — its `open()` hard-fails with "no codec configured", and at priority 50 it outranks the null backend for both directions. Gate registration on a codec being present (the file's own comment says boards should do this).
- `drivers/audio.c` `audio_open_playback()` / `audio_open_capture()`: walk the backend list in priority order and fall through when `open()` fails, so a refusing backend can never mute the HAL.
- `drivers/audio.c` `mixer_scale()`: make rounding sign-symmetric so `-10000` and `10000` scale to the same magnitude.
- `kernel/selftest_audio.c:64-65`: the expected half-volume value `5023` matches no formula — `(10000*128 + 127)/255` is `5020`. Correct the two constants to `5020` / `-5020`.

### 6. Modem: stale AT completion state + call/SMS event gaps (fixes ~11 `modtest` failures)
- `drivers/modem.c` `q_submit_wait()`: reset `q_done`, `q_nlines`, `q_status` before submitting. Currently `q_done` stays true after the first command, so `AT+CREG?`/`AT+CSQ` return instantly with the previous command's lines and leave the engine desynchronized — which is what then makes `dial submitted` fail and strands the FSM in `CALL_DIALING`.
- Route `modem_dial()`, `modem_answer()`, `modem_hangup()` through the same reset helper.
- Feed the AT response status into the FSM: apply `CALL_EV_OK` / `CALL_EV_ERROR` on completion so `CALL_ENDING` reaches `CALL_IDLE` after `ATH`, and `ATA` promotes `CALL_INCOMING` to `CALL_ACTIVE`.
- Notify call observers on locally-driven transitions (today only `urc_line` does), so the audio-route hook fires.
- `drivers/modem.c` `urc_line()`: check the pending-`+CMT` state first and route the following hex PDU line to `modem_sms_sink_line()`. Today only the `+CMT:` header is recognized and the PDU body falls through to `kprintf("modem: urc …")`.
- Copy response lines in `q_collect` instead of stashing pointers into `eng.resp_store`, which the next command overwrites.

### 7. Block layer overflows the caller's buffer on sub-sector I/O (fixes the 21-failure `reltest` A/B cascade)
`block_read()` accepts a byte count, but the cached single-sector path memcpy's a full 512 bytes into the caller's buffer. `abmgr_attach()` passes an 80-byte `struct ab_table`, so the read scribbles ~432 bytes over adjacent `.bss`.
- `drivers/block.c`: bounce sub-sector transfers through a sector-sized temporary and copy only the requested bytes (both read and write directions).
- `drivers/block.c:99` also prints `0 MiB` for the 32 KiB ramdisk; switch to KiB when the device is under a MiB.

### 8. Watchdog heartbeat check is timing-racy
- `kernel/selftest_release.c:218`: `st.kicks > 100` depends on how much CPU the housekeeping task happened to get. Sample `kicks`, sleep a bounded interval, and assert it advanced.

### 9. Serial output interleaving
- `kernel/syscall.c` `console_write_raw()`: it emits byte-by-byte with `uart_putc()` and never takes the UART tx lock, so userspace writes cut into kernel lines. Wrap each copied chunk in `uart_tx_begin()`/`uart_tx_end()` — the lock `kprintf` and `tty_emit` already use.

### 10. `fork` does not inherit shm attachments (fixes the ipcdemo data abort)
FAR `0x300000004` is `USER_SHM_BASE + 4`: the child inherits the pointer value but `proc_do_fork` copies only L0 range `[2,6)` and never replicates `parent->shm_maps[]`, so L0[6] is empty.
- `kernel/ipc.c`: add `ipc_proc_fork(child, parent)` that re-maps the same frames (not copies — `vmm_copy_space` would un-share the object) and bumps `attaches`.
- `include/ipc.h`: declare it; `kernel/proc.c` `proc_do_fork()`: call it after `mmap_next` is copied, unwinding the child on failure. Teardown already handles it via `ipc_proc_exit()`.

### 11. `pthread_create` hands the new thread a pointer into its own dead frame (fixes the libctest PC-alignment fault)
`struct iarg ia` is a local of `pthread_create`, which returns before the thread runs; `pthread_join`'s prologue then reuses that stack slot, and the trampoline loads `&checks` as its tcb and branches to `checks | (fails << 32)` — exactly the reported `0x400000016`.
- `userspace/libc/pthread.c`: move `armed` into `struct tcb` (which lives in the thread's own mmap'd page), delete `struct iarg`, pass the tcb as the clone argument, and publish `armed` with a release store.
- Optional hardening: seed `tf->regs[30]` in `kernel/proc.c:1348` to a `SYS_thread_exit` stub so a stray `ret` traps meaningfully instead of jumping to 0.

### 12. `sbrk: grow` is a test-side bug
`userspace/libc/malloc.c` returns the *old* break — correct Unix semantics — so `sbrk(0)` then `sbrk(32)` yield equal pointers and `nxt > cur` can never hold.
- `userspace/libctest.c:95`: assert `nxt == cur`.

### Not fixed — environmental under `make run`
